# SimplePromptDataEngineering

**Prompt Engineering for Data Engineering** — A complete, production-style demonstration of how Large Language Models (LLMs) can automate and accelerate every stage of a modern data engineering pipeline.

## Use Case: E-Commerce Sales Analytics

This project processes raw e-commerce data (orders, customers, products) through a **Medallion Architecture** (Bronze → Silver → Gold → Reports), using **OpenAI GPT** prompt engineering at every ETL stage.

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ Raw Data │───▶│  Bronze  │───▶│  Silver  │───▶│   Gold   │───▶│ Reports  │
│ (CSV)    │    │  Layer   │    │  Layer   │    │  Layer   │    │ (MD/JSON)│
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
                 LLM: Schema     LLM: Clean      LLM: KPI       LLM: Narrative
                 Detection       & Transform     Aggregation     Insights
```

---

## How Prompt Engineering Is Used at Each Layer

| Layer | Traditional Approach | Prompt Engineering Approach |
|-------|---------------------|---------------------------|
| **Bronze** | Manually write schema definitions, profiling scripts | LLM auto-detects schema, profiles data quality, generates metadata |
| **Silver** | Hand-code cleaning rules, transformation logic | LLM generates Pandas cleaning code + join/enrichment logic |
| **Gold** | Write SQL/Pandas aggregations manually | LLM generates KPI calculation code from natural language |
| **Reports** | Build dashboards, write summaries manually | LLM generates executive narratives, anomaly detection, recommendations |

## Runbook: Step-by-Step Implementation Guide

### Prerequisites

- Python 3.9+
- OpenAI API key ([get one here](https://platform.openai.com/api-keys))
- (Optional) AWS account with S3 access for cloud storage

### Step 1: Clone & Setup

```bash
git clone https://github.com/sunkaramallikarjuna369/SimplePromptDataEngineering.git
cd SimplePromptDataEngineering

python -m venv venv
source venv/bin/activate        # Linux/Mac
# venv\Scripts\activate         # Windows

pip install -r requirements.txt
```

### Step 2: Configure Environment

```bash
cp .env.example .env
```

Edit `.env` and set your OpenAI API key:

```
OPENAI_API_KEY=sk-your-actual-key-here
OPENAI_MODEL=gpt-4              # or gpt-3.5-turbo for lower cost
STORAGE_BACKEND=local            # or "s3" for AWS
```

### Step 3: Run the Full Pipeline

```bash
python main.py
```

This runs all four layers sequentially:

1. **Bronze** — Reads raw CSVs, uses LLM to detect schemas and profile data quality
2. **Silver** — LLM generates cleaning rules and transformation code, executes them
3. **Gold** — LLM generates aggregation logic for daily sales, customer analytics, product performance
4. **Reports** — LLM generates an executive report and anomaly analysis

### Step 4: Run Individual Layers

```bash
python main.py --layer bronze    # Only raw ingestion + schema detection
python main.py --layer silver    # Only cleaning + transformation
python main.py --layer gold      # Only aggregations + KPIs
python main.py --layer reports   # Only report generation
```

### Step 5: Review Outputs

After running, check the output directories:

```bash
# Bronze: Schema metadata generated by LLM
cat data/bronze/orders_metadata.json

# Silver: LLM-generated cleaning rules (actual Python code)
cat data/silver/orders_cleaning_rules.py
cat data/silver/transformation_rules.py

# Gold: Business metric tables
cat data/gold/daily_sales_summary.csv
cat data/gold/customer_analytics.csv
cat data/gold/product_performance.csv

# Reports: LLM-generated executive report
cat data/reports/executive_report.md
cat data/reports/anomaly_report.json
```

## Detailed Layer Descriptions

### Bronze Layer — Raw Ingestion with LLM Schema Detection

**What happens:**
1. Reads each raw CSV file from `data/raw/`
2. Sends column headers + sample rows to LLM
3. LLM returns a JSON schema (data types, nullable flags, format patterns, primary keys)
4. LLM profiles data quality (quality score, issues, recommendations)
5. Saves raw data copy + metadata to `data/bronze/`

**Key Prompt:** The LLM analyzes sample data and infers schema, data types, and quality issues — replacing manual data profiling tools.

**Example LLM Output:**
```json
{
  "table_name": "orders",
  "columns": [
    {"name": "order_id", "data_type": "string", "nullable": false, "description": "Unique order identifier"},
    {"name": "order_date", "data_type": "date", "format_pattern": "mixed formats detected"}
  ],
  "quality_notes": ["order_date has inconsistent date formats (ISO, US, text)"]
}
```

### Silver Layer — LLM-Powered Data Cleaning & Transformation

**What happens:**
1. For each bronze table, sends schema + profile to LLM
2. LLM generates a complete Python cleaning function (handles date formats, nulls, dedup, etc.)
3. Executes the LLM-generated code (with fallback if it fails)
4. Sends all cleaned tables to LLM for transformation rules
5. LLM generates join + enrichment code (derived columns, time dimensions)
6. Saves cleaned tables + enriched dataset to `data/silver/`

**Key Prompt:** The LLM writes actual executable Pandas code to clean and transform data — replacing hours of manual ETL development.

**What gets generated:**
- `orders_cleaning_rules.py` — Auto-generated date parsing, null handling
- `transformation_rules.py` — Auto-generated joins, calculated fields (revenue, profit, margins)

### Gold Layer — LLM-Generated Business Aggregations

**What happens:**
1. Sends silver schema + sample data to LLM
2. LLM generates aggregation code for three gold tables:
   - `daily_sales_summary` — Revenue, order count, AOV per day
   - `customer_analytics` — CLV, purchase frequency, segmentation
   - `product_performance` — Revenue, margins, units sold per product
3. Executes aggregation code (with fallback)
4. Saves to `data/gold/`

**Key Prompt:** The LLM translates business KPI requirements into Pandas aggregation code automatically.

### Report Generation — LLM-Powered Narrative Insights

**What happens:**
1. Feeds gold table summaries + overall metrics to LLM
2. LLM generates a professional executive report in Markdown with:
   - Executive Summary
   - Revenue Analysis
   - Customer Insights
   - Product Performance
   - Anomalies & Alerts
   - Top 5 Recommendations
3. Runs anomaly detection via LLM (statistical outliers explained in business context)
4. Saves to `data/reports/`

**Key Prompt:** The LLM acts as a business analyst, turning raw numbers into actionable narratives.

## AWS S3 Integration

To use AWS S3 instead of local storage:

1. Set environment variables in `.env`:
```
STORAGE_BACKEND=s3
AWS_ACCESS_KEY_ID=your-key
AWS_SECRET_ACCESS_KEY=your-secret
AWS_REGION=us-east-1
S3_BUCKET=your-bucket-name
```

2. Upload raw data to your S3 bucket under `data/raw/`
3. Run the pipeline — all outputs go to S3

The `StorageManager` class transparently handles both local and S3 backends.

## Prompt Engineering Best Practices Used

| Practice | Where Used |
|----------|-----------|
| **System + User prompt separation** | All LLM calls — system prompt sets the role, user prompt provides data |
| **Structured output (JSON)** | Bronze schema detection, data profiling, anomaly detection |
| **Code generation prompts** | Silver cleaning rules, transformation rules, gold aggregations |
| **Few-shot context** | Sample data rows provided in every prompt for context |
| **Role-based prompting** | Each prompt assigns a specialist role (data engineer, analyst, BI engineer) |
| **Fallback handling** | Every LLM-generated code has a deterministic fallback |
| **Temperature control** | Low temperature (0.2) for deterministic, reproducible outputs |

---

## Key Design Decisions

1. **LLM-Generated Code with Fallback** — Every layer tries LLM-generated code first, falls back to deterministic logic if it fails. This ensures the pipeline always completes.

2. **Code Artifacts Saved** — All LLM-generated Python code is saved to disk (e.g., `cleaning_rules.py`, `aggregation_rules.py`) so you can inspect, version, and reuse them.

3. **Modular Architecture** — Each layer is independent and can be run separately. The pipeline supports incremental execution.

4. **Cloud-Agnostic Storage** — The `StorageManager` abstracts local vs. S3, making it easy to switch between development and production.

## Extending This Project

- **Add more data sources** — Drop new CSVs into `data/raw/` and the pipeline auto-detects schemas
- **Switch LLM providers** — Replace `llm_client.py` with Azure OpenAI, Anthropic Claude, or local models
- **Add scheduling** — Wrap `main.py` with Apache Airflow, Prefect, or AWS Step Functions
- **Add data validation** — Integrate Great Expectations using LLM-generated expectation suites
- **Scale with Spark** — Replace Pandas with PySpark for large datasets
